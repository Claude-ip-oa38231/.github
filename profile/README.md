<h2>一、先弄清分线分的是哪几层</h2>
<p>多数人说的分线只等于换一个 IP，这个理解不够用。真正会让两个号被关联的，是出口、会话、资料三层同时暴露：出口层看 IP 归属城市和 ASN，会话层看 Cookie、时区、语言是否与出口一致，资料层看注册手机号段、支付方式和常用登录时段。只改其中一层，另外两层照样把关系摆在那里。</p>

<h3>出口层：归属地和 ASN 是两条独立信息</h3>
<p>用 curl -s https://ipinfo.io/json 拉一次，重点看 city、org、timezone 三个字段。city 要和账号资料里的城市对得上；org 里出现的应该是家宽运营商名字，出现 hosting、cloud、datacenter 这类字样就说明是机房段。ASN 再单独查一次，同一个 /24 里如果家宽和 IDC 混在一起，说明这段是混播的，重要老号别往上放。</p>

<h3>会话层：指纹和出口必须成套</h3>
<p>时区错位是最常见的破绽：出口在洛杉矶，浏览器时区还停在东八区，语言列表只有中文，这种组合比 IP 本身更显眼。做法很朴素，一个账号一个 profile 目录，启动参数里把语言、时区、分辨率一次写死，不要用随机化插件去抖，随机出来的组合反而更容易撞上异常值。</p>

<h2>三、老号和新号的分线策略不一样</h2>
<h3>老号：保稳定优先，别轻易搬家</h3>
<p>养了三个月以上、有正常付费记录的号，出口能不换就不换。真要换，挑同城同运营商的另一条线，别跨 ASN。换之前把当前环境整目录打包，出问题十分钟内能切回去，这个动作比任何检测脚本都实用。</p>

<h3>新号：先占位，再放量</h3>
<p>新号第一批不超过五个，每条线挂一个，观察七十二小时。看三件事：登录是否需要额外验证、对话响应有没有被降级、后台是否出现异常提示。三天都平稳，再按每周翻倍的节奏加号。翻倍慢，但出问题时影响面小；赶进度最多一次翻三倍，再多就不叫放量了。</p>

<h2>四、开新地区市场，换线顺序别搞反</h2>
<h3>先加线，再迁号</h3>
<p>正确顺序是先把新地区的出口开出来，单独跑一天看延迟和稳定性，确认没问题再把对应的号迁过去。反过来先改号的环境再等线，中间那段时间号一直处在「资料写 A 地、出口在 B 地」的状态里，最容易出岔子。这个顺序看着是小事，实际是整件事里最容易省错的一步。</p>

<h3>换线后一天内盯三个指标</h3>
<p>一是首包延迟，正常住宅线到目标地区大多落在 150 至 260 毫秒，突然掉到 80 毫秒以下反而要警惕，可能是被调度到机房中转；二是丢包率，超过 3% 就联系服务商换线；三是登录验证触发次数，一天超过两次说明这条线在你之前已经被别人用脏了，别急着怪自己的环境。</p>

<h2>常见问答</h2>
<h3>同一个号白天用住宅线、晚上用机房线，会出问题吗？</h3>
<p>答：会。出口类型在一天内反复切换，等于告诉平台这个账号的使用者在两地之间瞬移。要么全程住宅，要么把机房线只留给不登录的公开数据抓取，两条线不要挂在同一个登录态上。</p>

<h3>机房 IP 是不是完全不能用？</h3>
<p>答：不是。公开文档抓取、静态资源下载这类不涉及登录的动作，机房线又快又便宜。敏感的是登录态和付费动作，这些环节对出口类型更挑剔，用机房段等于给自己加难度。</p>

<h3>老号换线之后要不要重新养一段时间？</h3>
<p>答：要，但强度可以降一档。换线后前三天保持每天固定时段登录一次、做两三次正常对话，不要一上来就跑批量任务。三天内没有异常提示，再恢复原来的使用强度。</p>

<h3>一个号配一条线，成本会不会太高？</h3>
<p>答：按量计费时，一个号一条独享住宅线每月大概几十到两百元不等，地区不同差别不小，仅供参考。把这个数字和「一个号被牵连后重新养号的成本」放在一起比，多数情况下分线更划算。</p>
